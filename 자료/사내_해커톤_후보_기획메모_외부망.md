# 사내 해커톤 후보 기획 메모 — 외부망 활용형

> 용도: 내부망 후보 메모와 함께 추후 최종 계획서(Word) 작성 시 컨텍스트 복원용.
> 제출용 문서가 아니라 현재까지의 결정사항·의도·미확정 체크포인트 보존용.
> 외부망 정식 후보는 AI News Intelligence 1개. AI·금융 동향 Reader는 장기 확장(Source Reader / Watchlist)으로 흡수.
> CSV/Excel → 보고서 자동 생성은 제외. 사내 보고서별 양식 차이가 커 범용성이 낮다고 판단.

---

# 0. 공통 전제

- 사내 문서/데이터는 외부망에서 사용하지 않음. 공개 데이터만 사용.
- GitHub Copilot은 회사 제공 유료 계정 활용.
- Gemini Developer API는 Copilot/Gemini 앱 구독과 별개. Google AI Studio API Key 사용.
- 개발용 검색/AI 조합: `Gemini 2.5 Flash + Google Search Grounding` 우선 검토.
- 해커톤 시작 시 무료 한도/정책 최신 상태 재확인.
- API Key는 `.env`, Secrets 등으로 분리하고 GitHub에 포함하지 않음.
- 동일 검색 반복 호출 방지를 위해 실제 검색 결과를 JSON 등으로 캐시.
- 수동 Deep Research를 기본 개발방식으로 두지 않고 실제 검색이 동작하는 MVP를 지향.

# 1. AI News Intelligence

## 목적

현재 사내에는 사람이 외부망에서 주요 신문 1면 기사, 회사 관련 기사, 금융·증권 주요 기사 등을 선별해 기사별 1~2줄 요약과 링크를 메일로 공유하는 업무가 있음.

기존 방식은 `어떤 기사가 나왔는가`를 확인하기에는 유용하지만, 동일 이슈에 대해:
- 여러 언론사가 공통적으로 확인하는 사실
- 특정 출처만 추가로 보도한 내용
- 매체/출처별 관점 차이
- 내용 충돌/불확실성
- 현재 얼마나 많이 언급되는지
- 기사량은 적더라도 업무상 주의해야 하는 사안인지

를 파악하려면 여러 기사를 직접 읽어야 함.

목표는 기존 뉴스 메일의 단순 자동화/대체가 아니라:
**뉴스 전달 → 이슈 단위 조사·교차분석**으로 확장하는 것.

최종 결과의 기본 단위는 `기사`가 아니라 `이슈`.

# 2. 사용자 조사 조건

## 관심 주제
기본 선택지 예:
- AI
- 금융
- 증권
- 경제
- 정책·규제

복수 선택 가능. 사용자가 직접 키워드 추가 가능.

예:
```text
☑ AI
☑ 금융
☐ 증권

직접 입력
[ 금융보안 ] [추가]

AI ×  금융 ×  금융보안 ×
```

사용자 직접 입력 키워드는 해당 조사에서만 사용. 관리자 공통 키워드에 자동 등록하지 않음.

## AND / OR
복수 주제 선택 시 사용자가 검색 관계 선택.

OR:
- 선택 주제 중 하나 이상과 관련된 뉴스를 폭넓게 조사.

AND:
- 선택한 주제들이 교차하는 영역을 조사.

주의:
- 단순 문자열 AND로 할지
- `선택 주제들의 의미상 교집합`을 AI로 판단할지
- 혼합할지
는 팀 논의 후 결정.

## 조사 기간
시작일/종료일 직접 설정.

너무 짧으면 이슈 비교에 필요한 기사 부족 가능.
너무 길면 검색량/기사량/LLM 입력량 증가, 이슈 시점 구분 어려움.

최소/최대 기간 제한 필요.
초기 예시로 최소 2일/최대 30일을 생각했으나 미확정. 실제 테스트 후 결정.

# 5. 기사 수집 / 관련성 처리

Google Search Grounding으로 공개 웹/뉴스 검색.

검색된 모든 결과를 그대로 최종 분석하지 않음.

가능한 순서:
1. 관련 뉴스 후보 검색
2. 선택 주제와 관련성이 낮은 결과 제거
3. 동일/재배포 기사 중복 제거
4. 필요한 기사만 분석 대상으로 유지
5. 동일 사건/이슈끼리 그룹화

기사 전문을 무조건 대량으로 LLM에 넣는 구조는 피함.

가능하면 우선:
- URL
- 제목
- 출처
- 게시일
- 검색 snippet
을 활용하고, 필요한 경우에만 본문 활용.

구체적인 수집 범위/본문 확보 방식은 실제 Grounding 테스트 후 결정.

# 6. 이슈 단위 분석

예:
`수집 47건 → 관련 기사 31건 → 주요 이슈 5건`

기사 31개를 개별 요약하지 않고 이슈별로 압축.

각 이슈의 출력 후보:

### 핵심 내용
해당 이슈에서 실제로 어떤 일이 발생했는지 종합.

### 공통 사실
여러 기사/출처에서 공통 확인되는 사실.

### 추가 정보
일부 출처에서만 추가로 확인되는 내용.

### 관점 차이 / 쟁점
매체/출처별 강조점 또는 해석 차이.

### 확인 필요사항
기사 간 충돌, 불확실 정보, 추가 확인 필요사항.

### 관련 기사 / 출처
분석에 사용한 원문 링크 제공.

# 7. Hot / Critical

단순 `긍정/부정/중립` 감성분석은 제외.

## Hot
질문: **현재 얼마나 많이 언급되고 있는가?**

가능하면 AI 주관보다 수집 데이터 기반.

검토 요소:
- 관련 기사 수
- 서로 다른 매체 수
- 특정 기간 내 보도 집중도
- 보도량 증가 정도

예:
```text
HOT ●●●●○
관련 보도 23건 / 14개 매체
```

Hot = 많이 보도됨. 업무 중요성과 동일하지 않음.

## Critical
질문: **업무 관점에서 얼마나 주의 깊게 볼 필요가 있는가?**

검토 요소:
- 사안의 심각성
- 금융시장/금융회사 영향 가능성
- 규제/법률 영향
- 고객 영향
- 개인정보/보안 영향
- 공식기관 발표 여부
- 출처 신뢰도

예: 금융당국 수장이 금융권 해킹/보안 문제를 직접 언급한 사안은 기사량이 적어도 공식성·직접 영향·보안 심각성 때문에 Critical이 높을 수 있음.

```text
Issue A
HOT       ●●●●●
CRITICAL  ●●○○○
→ 많이 보도되지만 업무 영향은 상대적으로 제한적

Issue B
HOT       ●●○○○
CRITICAL  ●●●●●
→ 보도량은 적지만 업무상 확인 필요성이 높음
```

Hot/Critical 실제 산식·등급·AI/규칙 역할분담은 팀 논의 후 결정.

# 9. Gemini + Google Search Grounding 개발 전략

```text
GitHub Copilot
→ Python / Streamlit 개발 지원

Google AI Studio API
→ Gemini 2.5 Flash
→ Google Search Grounding
```

예:
```text

        ↓

        ↓
search_result_001.json
        ↓

```

검색 파이프라인 자체를 테스트할 때만 Grounding 재호출.

목적:
- 무료 API 한도 절약

- 동일 데이터로 반복 테스트

# 11. 1차 확장 — 이슈 추적

MVP가 예상보다 빠르게 완성됐을 때 우선 검토.

이전 조사 결과를 저장하여 같은 이슈 진행과정을 연결.

예:
```text
10/5 정책 개편 검토
 ↓
10/6 업계 의견수렴
 ↓
10/7 업계 입장 발표
 ↓
10/9 수정안 검토
```

표시 예:
> 이전 조사 대비 변화: 검토 단계 → 이해관계자 의견수렴 단계로 진전

필요:
- 이전 조사 결과 저장
- 동일 이슈 매칭
- 시간순 변화 분석

따라서 MVP 이후 기능.

# 12. 장기 확장 아이디어 — Source Reader / Watchlist

초기에는 별도 외부망 후보로 생각했으나 News Intelligence와 기술/기능 중복이 많아 확장 기능으로 통합.
해커톤 구현 우선순위 매우 낮음. 가능성만 기록.

관리자가 주요 공식/전문 출처 등록:
- AI 기업 공식 발표
- 기술 블로그
- GitHub Releases
- 금융위원회
- 금융감독원
- 한국은행
- 해외 금융당국
- 연구기관
- 공개 보고서

주기적으로 신규 자료 확인.

News Intelligence:
> 최근 이 주제에서 무슨 일이 있었고 여러 곳은 어떻게 보도했는가?

Reader:
> 내가 보는 공식 출처에서 무엇이 새로 나왔고 기존과 무엇이 달라졌는가?

Reader 핵심:
- 신규 자료 탐지
- 핵심 내용
- 이전 발표/버전 대비 변경점
- 업무 관련성
- 확인 필요사항

News Intelligence의 검색/관련성 판단/AI 분석/결과 표시 구조 재사용.

# 14. 주요 리스크

## 뉴스 수집 품질
Grounding 결과가 원하는 기사 범위/개수/기간을 항상 확보한다는 보장 없음. 실제 테스트 중요.

## 기사 원문 접근
출처별 기사 전문 접근 수준 차이로 교차분석 정보량이 달라질 수 있음.

## 동일 이슈 그룹화
- 비슷하지만 다른 사건을 합칠 위험
- 같은 사건을 여러 이슈로 나눌 위험

## Critical 판단
AI 주관 개입 가능. 단순 점수만 표시하기보다 `왜 Critical이 높은지` 근거 표시 검토.

## 범위 확대
검색 + 분석 + 이슈 추적 + 이메일 + Watchlist까지 한 번에 구현하면 실패 위험 증가.
MVP / 1차 확장 / 장기 확장을 명확히 분리.

## API 정책
Free Tier 정책/한도는 변경 가능. 해커톤 시작 시 최신 상태 확인.

# 15. 현재 최종 후보군

정식 후보 3개.

## 내부망
### 1. AI RFP 작성 지원

# 16. 추후 최종 Word 계획서 작성 시

내부망 기획 메모 MD + 본 MD를 함께 사용.

목적:
- 1회차 팀 구성/주제 선정 때 팀원들과 후보 논의용 약식 계획서.

중심으로 구성.
